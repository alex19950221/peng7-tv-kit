# 安装、布局与还原

先记录设备状态，再逐项安装并验证。此文档不修改系统固件，不提供一键开启所有权限的操作。

## 1. 记录自己的电视

在电视上启用 ADB 并授权自己的电脑，随后在此仓库运行：

```powershell
pwsh -File scripts/inspect-tv.ps1 -Address <电视的局域网IPv4地址> -AdbPath <adb可执行文件路径>
```

报告写入 `local/`，含电视地址和原设置，仅留本机。检查脚本只读电视设置；ADB 连接和报告写入是它的全部副作用。

## 2. 安装 Aerial

先阅读固定版本上游的 `docs/devices/tcl-mt5879-cn.md` 与实际机型文档。选择本地构建的 Release 包；上游在线安装命令可能下载官方签名版本，不能当作定制版更新方式。

本机固件拒绝直接 ADB 安装，通过 TCL 多屏互动推送 Guard 包成功。可参考固定版本源码中的 `tools/tcast-push.py`，由电视确认安装。其他机型可能接受常规安装；不要关闭系统安装校验来套用本案例。

需要 ADB 安装且支持基线 profile 的设备，Android 9–11 使用 APK 内 `assets/aerial-dm/28.dm`，Android 12+ 使用 `31.dm`，和 APK 以同文件名配对安装。具体以该机型验证为准。

## 3. 配置影音应用

独立安装自己的合法来源客户端，选择对应 Android 版本与 ABI 的包。版本与来源见 [兼容性记录](COMPATIBILITY.md)。仓库不提供下载镜像、安装助手或自动安装第三方应用的脚本。

在 Clash Meta 中导入自己的配置，完成首次 VPN 授权。桌面的「连接／断开」仅发送客户端公开命令，不保存订阅或密码；系统 VPN 图标不能证明具体节点或视频可播放。

Apple TV 需由使用者自行登录并拥有所需订阅。YouTube 在本机匿名试播时要求登录验证，由使用者自行完成后正常播放。不要向维护者提供账号、验证码或登录二维码。

## 4. 调整第一排

使用 Aerial 自带排序或电视显示的手机设置页，把 Apple TV 放在第 3 位、YouTube 放在第 5 位。原来的夸克和购物应用移到后面即可；这只是示例布局，不修改应用本身。

手机设置页地址含控制令牌，仅在自己的局域网使用。不要将实际地址、二维码或含令牌的截图放进 GitHub。

## 5. 桌面守护与恢复

是否启用无障碍桌面守护由设备所有者决定。启用时保留已有小 T 助手等服务；不要整串覆盖 `enabled_accessibility_services`。开机应用设置与 HOME 守护是两件事，须分别记录原值。

还原时重新读取当前设置，只撤销本项目新增的守护项，并恢复自己记录的开机组件；不要照搬别人的整串服务值。确认原桌面能打开、主页键能返回，再决定是否卸载定制版。布局、壁纸等数据的处理须先由使用者决定。

最后验证实体遥控器、原厂会员、HDMI、重启、待机唤醒，以及 VPN 的恢复；尚未验证的功能不要在自己的分享中标为通过。
