# YouTube 与 Apple TV 分流示例

`examples/mihomo-tv.example.yaml` 是独立编写的最小示例，不是实际使用中的订阅导出。节点地址使用保留示例域名，密码都是占位值；未替换之前无法联网。

| 分组 | 示例用途 |
| --- | --- |
| `YouTube-JP` | YouTube 页面、图片和视频流的常见域名 → 使用者自己的日本节点 |
| `AppleTV-US` | Apple TV 常见服务域名 → 使用者自己的美国节点 |

复制到本地 `local/mihomo-tv.yaml` 后编辑，或将示例规则合并到自己的订阅覆写中。不要编辑公开示例来填真实密码，也不要把原订阅 URL 写进 issue。

示例按域名匹配，不按整个应用匹配；广告、登录及共用服务域名可能命中其他规则。这里列出的域名不是平台完整清单，最后的 `MATCH,DIRECT` 明确表示未命中部分直接连接，实际合并时要保留自己需要的默认出口、DNS 和其他规则。较宽的通用规则应放在专用服务规则之后。

Clash Meta Android 的 VPN/TUN 和 DNS 设置由客户端管理。此示例不复制电脑的接口、DNS、控制端口或局域网监听设置，也不含远程规则提供方。导入后应检查客户端覆写，观察连接记录中的目标域名、命中规则和实际节点，再用自己的账号试播。

示例使用 HY2，开启证书校验，不设置虚高带宽。HY2 并不保证任何线路都更快；采用什么协议应以节点服务、网络支持和持续播放表现判断。

字段依据：[Mihomo Hysteria2 文档](https://wiki.metacubex.one/config/proxies/hysteria2/)。示例的区域名称描述配置意图，不能替代出口所在地、平台识别地区或账号地区的实际验证。
